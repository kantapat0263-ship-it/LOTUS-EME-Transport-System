# สรุปรายสัปดาห์และการแยกพัก

หน้า report มีแผงสรุปรายสัปดาห์เฉพาะแอดมินที่ยัง active อยู่ นอกพื้นที่ export JPEG เลือกวันในสัปดาห์แล้วกดโหลด ระบบปรับช่วงเป็นจันทร์–อาทิตย์ 7 วัน ไม่ส่งรายงานส่วนตัวหรือเหตุผลเข้ากลุ่ม LINE และไม่เพิ่มสิทธิ์ให้ลิงก์ใบงานสาธารณะ

ใช้ classifier เดียวกับ timeline และหมุดจอดใน tracking ตรวจจอดตั้งแต่ 15 นาทีตามเกณฑ์เดิมรัศมี 120 เมตร

- ในรัศมีออฟฟิศ 250 เมตรหรือจุดงาน 300 เมตร ไม่รวมในเวลารอตรวจสอบ งานโยกเข้า/โยกออก/เลื่อนใช้เงื่อนไขเดียวกับ tracking
- จอดทั้งหมดอยู่ใน 11:30–13:00 เวลาไทย ไม่เกิน 60 นาที เป็นพักเที่ยง
- จอดไม่เกิน 45 นาทีหลังขับต่อเนื่องที่มีหลักฐาน GPS อย่างน้อย 120 นาที เป็นพักระหว่างทาง หลักฐานขับต้องมีความเร็ว > 0 และพิกัดเคลื่อน หัวท้ายห่างไม่เกิน 5 นาที GPS เงียบตัดหลักฐานต่อเนื่อง การถึงจุดจอดไม่รีเซ็ตเวลาขับก่อนหน้า แต่ช่องว่างก่อนถึงเกิน 5 นาทีใช้ยืนยันไม่ได้
- ที่เหลือเป็นจอดนอกจุดงานรอตรวจสอบ ไม่ใช่ข้อสรุปว่าคนขับทำผิด GPS ขาดช่วงระหว่างจอดมีป้ายกำกับความไม่แน่นอน

รวมคนขับตาม `actualDriverId || driverId` และใช้ทะเบียน snapshot ใน trail ก่อนทะเบียนปัจจุบันของอุปกรณ์ วันอ้างอิง `trail.date` ตามวันติดตามที่ระบบเคยเก็บ ไม่เปลี่ยนวันประวัติ ตัด trail ตาม `gpsEndAt` ก่อนคำนวณ

ระยะเป็นค่าประมาณจาก GPS ที่มี เฉพาะคู่จุดไม่ขาดช่วงและไม่กระโดดผิดปกติ ไม่บวกระยะจากคู่จุดจอดที่ความเร็วทั้งคู่เป็นศูนย์ จำนวนวันแสดงเป็นวัน/คัน GPS ไม่มีระยะ จุดไม่พอ GPS ขาดช่วง หรือข้อมูลผิดปกติ จะไม่แสดงอัตรานาทีต่อ 100 กม. การไม่พบจุดจอดไม่ยืนยันว่าทั้งวันไม่มีเหตุ

รถทะเบียนเดียววันเดียวที่มีคนขับจริงหลายคน ไม่มีขอบเขตเริ่มที่น่าเชื่อถือ หรือมีหลาย trail ให้ระบุว่าแยกคนขับไม่ได้ ไม่แบ่งระยะ/จุดจอดซ้ำ และทำให้ coverage ของคนขับที่เกี่ยวข้องในสัปดาห์นั้นเป็นข้อมูลไม่พอ

แอดมินเปิดรายละเอียดวันเพื่อบันทึกเหตุผล เลือกตัดเวลารอตรวจสอบออก หรือยกเลิกการตัดพร้อมเหตุผลใหม่ เก็บผู้บันทึก เวอร์ชัน และ audit ก่อน/หลังใน transaction โดยไม่แก้ GPS ใบคิว booking หรือยอดแผน บันทึกไม่สำเร็จยังเก็บข้อความไว้ สามารถลองคำสั่งเดิมซ้ำได้อย่างปลอดภัย

`driverStopReviews` และ `driverStopReviewAudit` อ่าน/เขียนจาก server เท่านั้น Firestore rules เดิมปฏิเสธ browser SDK ทุกบทบาท API ตรวจ token และโปรไฟล์แอดมินสดทุกครั้ง คำสั่งตรวจ hash หลักฐาน GPS/งาน/ออฟฟิศ/การจับคู่รถกับเวอร์ชันเหตุผลก่อนบันทึก หลักฐานเปลี่ยน เหตุผลเดิมจะแสดงว่า stale และไม่ใช้ตัดสถิติจนแอดมินตรวจใหม่

อ่านรายงานด้วย `POST /api/reports/weekly-stops` `{weekStart}` เพื่อหลีกเลี่ยง service worker เก่าที่ cache API GET ตาม URL; GET ตอบ 405 โดยไม่ส่งข้อมูลส่วนตัว บันทึกเหตุผลใช้ `POST /api/reports/weekly-stops/review` ทุก response มี `private, no-store` และ client timeout 45 วินาทีรวมรอ token

ขอบเขตการอ่านครั้งละสัปดาห์ไม่เกิน 1,000 ทริป 350 trail 500 รถ 2,000 เหตุผล และ 5,000 จุดจอด เกินขอบเขตตอบข้อผิดพลาด ไม่สรุปบางส่วนแบบเงียบ ๆ การอ่านจะเกิดเมื่อกดโหลดหรือหลังบันทึกเหตุผลสำเร็จ จึงไม่เพิ่มงาน polling background
